# 开发记录

这里是世界色彩地球的版本历史和几次大改造的细节（测试方法、帧率数据、取舍），概览见 [README](../README.md)。

## 版本记录

第 1–12 版发布在 claude.ai 的 Artifact 页面上；从第 13 版起只在这个仓库和桌面版里更新。

1. 地球初版：可旋转，可按国家上色，能打开平面图。
2. 加入放大功能；调整底图边界；五大湖改为镂空。
3. 调整部分边界。
4. 平面图里可以给一级行政区单独上色；加入东西德分界线，当时是用今天的州界近似拼成的。
5. 加入全世界二级行政区；拆分东西柏林；分界线换成 OpenHistoricalMap 的历史数据。
6. 第 6、7 版：给二级行政区编固定代码，地球上可以直接按一级或二级行政区上色，可以输入代码批量涂色；调整部分边界。
7. 第 8 版：平面图行政区名称的字号可以调节。
8. 第 9 版（2026-11-05）：地球改用 WebGL 绘制，拖动和静止都是 1:10m；加了帧率显示开关；读数据、存文件和读写配置抽成平台接口层；修好点在 180° 经线或南极点上时判断不出国家的问题。同时有了 Electron 桌面版。这次只更新了页面，数据文件没有变化。
9. 第 10 版（2026-11-05）：按住 Option（Alt）点击可以直接还原成未涂色；德国行政区与东西德分界线对齐，诺伊豪斯单独成块。更新了页面和德国相关的 5 个数据文件，现有的行政区代码都没有变。
10. 第 11 版（2026-11-05）：边界小调整；界面主题可选；页面标题前加上新标志。更新了页面和 4 个数据文件（国家轮廓、两个国家的一级行政区，以及重建时被顺带改动的斯里兰卡二级文件，见下文）。
11. 第 12 版（2026-11-06）：阵营图层和一键涂色、国旗、中英文界面。更新了页面，新增一个数据文件 `flags.json`。
12. 第 13 版（2026-11-05）：搜索国家时转到首都并放大到整个国家；标题、操作按钮和搜索框合成顶部一行，窗口窄于 1320 像素时，操作按钮和搜索框换到标题下面一行；界面改成柔和风格（大圆角、无硬边框、带色调的柔和阴影，主色为低饱和靛蓝 #5b5fc7，设置分组改成卡片，触屏上可点的目标至少 44 像素高），地图本身的颜色不变；“配置 JSON”里可以直接导入 .json 文件。只改了页面，数据文件没有变化。从这一版起不再发布到 Artifact 页面。
13. 第 14 版（2026-11-06）：边界小调整（丹麦平面图多了一个插图，旧配置里的相关代码自动迁移，现有的二级行政区代码不变）；修好地球画布比实际小 2 像素的问题，之前点击会偏 1 像素，图也有极轻微的拉伸，2 公里宽的小岛可能点不中。更新了页面和 3 个数据文件。
14. 第 15 版（2026-11-08）：界面改成左右两个可收起的侧栏，整页固定在一屏里不再滚动；设置卡片可以折叠、隐藏、调整顺序和换边；删掉了地图下方的边界说明小字；桌面版每次修改自动写回项目文件，下次启动时自动打开上次的项目。只改了页面和桌面版主进程，数据文件没有变化。

## 桌面版和 WebGL 改造记录

**第一步：帧率显示和改造前基准（2026-11-05）。** “底图”里加了“显示地球的帧率和每帧耗时”开关，读数在地球左下角，依次是绘制方式、帧率、平均帧间隔、95% 分位帧间隔和每帧绘制耗时。开关状态单独存在浏览器里，不写进配置 JSON。`test/bench.mjs` 会打开一个带窗口的 Chrome（本机 Apple M4 GPU，Retina 两倍像素），在页面里模拟连续拖动 4 秒，去掉前 0.4 秒后统计。用法是 `node test/bench.mjs "" plain`，每次只跑一个用例，连续跑多个时第二个浏览器偶尔会卡住。

改造前的 Canvas 2D 版本，地球画布 1062×555，像素比 2，测了三轮，数字很稳定：

| 情况 | 拖动帧率 | 平均每帧 | 95% 分位 | 每帧绘制 | 松手后 1:10m 重绘 |
|---|---|---|---|---|---|
| 未放大 | 21–22 fps | 46–47 ms | 55 ms | 46 ms | 332 ms |
| 放大到 5 倍 | 60 fps | 16.7 ms | 17 ms | 8 ms | 50 ms |
| 打开行政区线 | 19–20 fps | 51 ms | 61 ms | 50 ms | 346 ms |

放大到 5 倍时能到 60 帧，是因为只画屏幕范围内的形状，而且拖动时用的是 1:50m 简化轮廓，并不是 1:10m。

**第二步：平台接口层（2026-11-05）。** 读数据、保存文件、读写配置三件事抽到了 `src/platform.js`，页面只调用 `platform.data()`、`platform.files()`、`platform.config.load/store/baseline()` 和 `platform.pref()`。网页版的实现和原来完全一样：相对路径 fetch、Artifact 的 downloads 能力、localStorage。页面里检测到 Electron preload 暴露的 `window.globeHost` 时换成桌面实现：数据经 `app://globe/data/` 自定义协议从本地读取，导出走系统保存对话框，配置存在 `.json` 项目文件里（格式就是原来的配置 JSON）。`scripts/assemble.mjs` 现在同时产出两份页面：网页版仍是单个 `dist/index.html`，`platform.js` 被内联进去；桌面版在 `desktop/app/`，d3、topojson 和字体都复制到本地，样式和脚本拆成单独的文件，以便使用严格的内容安全策略。

验证：`test/interactions.mjs` 和 `test/denmark.mjs` 在网页版上照常通过，结果和改造前一致。新增 `test/desktop.mjs`，在测试模式下启动 Electron（对话框由测试自动应答，文件写到临时目录），确认了打开旧项目时旧的单位代码自动迁移、改动后标题出现 ●、保存后标记消失且文件内容正确、撤销后标记重新出现、导出 PNG（2400 像素宽）和 SVG、新建、最近打开、关闭前提示和取消、页面里拿不到 `require` 和 `process`、字体全部从本地加载、注入的内联脚本和外网请求都会被 CSP 拦下。

**第三步：WebGL 地球（2026-11-05）。** 地球改由 `src/globe-gl.js` 用 WebGL2 绘制，平面图仍是 SVG。做法如下：

- 网格在页面打开时生成：先用 1:50m 轮廓，1:10m 数据到达后分片切好再替换（每片不超过 12 毫秒，不卡界面）。每个多边形先转成单位球上的三维点，长于 1° 的边按大圆插值加密；再以多边形中心做心射投影（太大的形状改用等距方位投影），用 earcut 三角化；最后把三角形按大圆中点反复对分，直到每条边都不超过 2°，这样地球边缘不会露缝，相邻三角形之间也不会出现 T 形裂缝。南极洲沿 180° 经线和极点绕的那圈切缝点会被去掉，俄罗斯、斐济在 180° 处切开的各块照常保留。1:10m 共 58 万个顶点、60 万个三角形，在 Node 里切完约 0.5 秒，各国三角形面积与 d3 球面面积的误差在万分之一以内（只有几个小环礁约 1%）。
- 旋转和缩放只更新 uniform，投影与 `d3.geoOrthographic().rotate()` 完全一致，地球背面用面剔除加深度判断去掉。
- 颜色放在一张小纹理里，每个国家和每个涂过的行政区各占一个位置。涂色只改纹理；第一次涂某个行政区时，把它单独切好追加到行政区缓冲区，国家网格不重建。斜线在片元着色器里按屏幕坐标生成，周期 9 像素、线宽 2.6 像素，和 Canvas 版的图案对齐。
- 国界海岸线、行政区线、经纬网、东西德分界线和海上分界线都用实例化四边形绘制，线宽按屏幕像素算，并在着色器里做抗锯齿。每层线条先以 MAX 混合画进离屏缓冲区的一个通道，再统一叠到地图上，所以 1:10m 海岸线密集的地方不会因为线段重叠而发黑，透明度和 Canvas 版逐层描边的效果一致。
- 拖动和静止都用 1:10m 全量（按既定方案），松手后不再切换精度。
- 悬停高亮和区县界线仍画在原来的 Canvas 2D 叠加层上。点击判断沿用经纬度反算加 geoContains（按既定方案），并修了一个原有问题：坐标恰好落在 180° 经线或南极点上时，geoContains 会判断不出来，现在会先往里挪 0.0001° 再判断。
- PNG 导出：用 WebGL 按 2400 像素宽离屏绘制后读回像素。SVG 导出沿用原来的 d3 路径。
- 浏览器不支持 WebGL2、着色器编译失败或上下文丢失时，自动回到原来的 Canvas 2D 绘制；上下文恢复后会重新启用 WebGL。

拖动帧率（同一台 M4 MacBook，Chrome 有窗口模式，像素比 2）：

| 情况 | 改造前 Canvas 2D | WebGL（60 Hz 屏幕） | WebGL 不限帧率 |
|---|---|---|---|
| 未放大 | 21–22 fps，每帧 46 ms | 60 fps，95% 分位 17.6 ms | 180 fps，每帧 5.6 ms |
| 放大到 5 倍 | 60 fps（拖动时只用 1:50m） | 60 fps，1:10m | 246 fps，每帧 4.1 ms |
| 打开行政区线 | 19–20 fps，每帧 51 ms | 60 fps，95% 分位 17.6 ms | 159 fps，每帧 6.3 ms |

`test/webgl.mjs` 分四批验证（`spots`、`compare`、`features`、`fallback`），全部通过。`spots` 用真实鼠标点击并读取 WebGL 像素，覆盖了楚科奇在 180° 两侧、斐济（维提岛、跨 180° 的塔韦乌尼、180° 以东的拉克巴）、南极点、南极洲 180° 切缝、格陵兰（命中丹麦）、苏必利尔湖、密歇根湖和伊利湖（不命中任何国家，显示海洋色）、几处边界调整过的地方、东西柏林（悬停显示西柏林和东柏林），海上分界线和东西德分界线的深色像素数也和 Canvas 版相当。`compare` 在五个视图下比较 WebGL 和 Canvas 2D 的画面（含斜线和行政区线），差异超过 48/255 的像素只占 0.04%–0.16%，对比图存在 `work/compare-*.png`。`features` 验证了 WebGL 模式下悬停显示区县代码（USA-0628）、悬停轮廓、涂区县时国家网格三角形数不变、滚轮和按钮缩放、PNG（2400×1254，中心像素就是涂色）和 SVG 导出。`fallback` 在关闭 WebGL 的情况下重跑全部地点。`test/mesh.mjs` 在 Node 里检查三角化。原有的两个测试也照常通过。

还有几处和 Canvas 版不完全一样：东西德分界线的虚线按球面弧长计算，靠近地球边缘时会被压缩，虚线端头是方的，不是圆的；1:10m 网格在打开页面约 3 秒后才就绪（包含下载 3.5MB 数据），在此之前显示 1:50m。另外滚轮缩放时，指针下的位置会偏一点（连续放大 6 次约 0.8°），这是原有缩放算法的近似误差，这次没有改动。南极洲的罗斯冰架、龙尼冰架在 Natural Earth 国家数据里本来就算海洋，两个版本都显示为海洋、点击不命中。

**第四步：Electron 外壳和打包（2026-11-05）。** `desktop/main.mjs` 是主进程，窗口开启 `contextIsolation` 和 `sandbox`，关闭 `nodeIntegration`。页面只能通过 `desktop/preload.cjs` 暴露的 `window.globeHost` 读写项目、保存文件和偏好设置。页面和数据都经 `app://globe/` 协议提供，协议只允许读 `desktop/app/` 和数据目录里的文件，响应头和页面里都带内容安全策略：只允许本地脚本、样式、字体和数据，不允许内联脚本、eval 和任何外网请求。d3、topojson、earcut 和三套字体（IBM Plex Sans、IBM Plex Mono、Inter，均为 SIL OFL）都打包在本地，许可文件放在旁边，可以完全离线使用。中文仍用系统的苹方。

菜单栏有：文件（新建、打开、最近打开、保存、另存为、导出 PNG、导出 SVG、关闭窗口）、编辑（撤销，焦点在文本框里时撤销文字输入，否则撤销涂色；还有剪切、复制、粘贴、全选）、显示和窗口。项目文件就是原来的配置 JSON，网页版“配置 JSON”里复制出来的内容也能直接打开，旧配置照常迁移。窗口标题显示文件名，有未保存的修改时前面加 ●，macOS 的关闭按钮也会显示修改标记。新建、打开、关闭窗口或退出前，如果有未保存的修改，会询问保存、不保存还是取消。最近打开的文件和导出目录记在用户数据目录的 `settings.json` 里。

网页版当时发布到 claude.ai 的 Artifact 页面，成为第 9 版。这次只替换了页面，411 个数据文件沿用线上原有的（发布前核对过，线上页面里的内嵌数据和本地一致，也没有本地缺少的改动）。

`npm run dist:mac` 用 electron-builder 26 打包 Apple Silicon 版，输出 `release/world-globe-1.0.0-arm64.dmg` 和 `.zip`，各约 125MB，其中 50MB 是地图数据，作为 Resources/data 放在包里。我启动打包后的应用确认过：数据从包内读取，WebGL 1:10m 正常，没有报错。按计划这次还没有签名和公证，应用只带 ad-hoc 签名，图标也还是 Electron 的默认图标。在本机直接打开没有问题；复制到别的 Mac 后，第一次要右键选择“打开”，或者在“系统设置 › 隐私与安全性”里放行。

Electron 版的拖动帧率（窗口 1440×960，地球画布 1062×666，比 Chrome 里的大一些）：未放大、放大到 5 倍、打开行政区线三种情况都是 60 fps，95% 分位帧间隔 17.2–17.3 ms；不限帧率时分别是 174、236、161 fps。作为对照，在 Electron 里强制使用 Canvas 2D，未放大拖动是 19.5 fps，打开行政区线是 18.4 fps。

**德国涂色和 Option 还原（2026-11-05，第 10 版）。** 按住 Option（Alt）点击会把当前单位直接还原成未涂色，不用先切换到“未涂色”画笔。德国行政区的处理见 README 的“边界设定”和“数据处理”第 3 步。对齐前，在分界线两侧 300 米处取点，一级行政区有 26% 落在错误一侧，二级有 5%；100 米处分别是 41% 和 16%。对齐后，300 米处两级都是 0；100 米处是 0.2% 和 0.1%，只剩分界线急弯处的几个点，量级和数据约 10 米的量化精度相当。重建数据时只有德国一级和二级文件、全球一级行政区线（`admin1-hi/lo.json`）发生了变化，现有代码全部不变。另外捷克的一级文件也被重写了，但只是一个环的起点换了位置，点集完全相同。`test/webgl.mjs germany` 验证了：Option 点击还原国家、一级行政区（地球上）和二级行政区（平面图上），普通点击照常涂色；沿分界线 496 个点两侧的归属在两级都正确。其余各批测试、原有测试和桌面版测试都重跑通过。

**第 11 版：边界小调整、界面主题、沉浸标题栏和标志（2026-11-05）。**

- **边界：**`build.sh` 调整了一组小岛的归属，国家和一级行政区两级保持一致。重建时只有国家轮廓、内嵌的 1:50m 轮廓和两个国家的一级文件按预期变化。斯里兰卡二级文件里，穆莱蒂武和亭可马里两个县各有三四个点挪了位置，面积差 0.003 km²，代码不变，是简化线条时的微小差异。`test/webgl.mjs spots` 新增了对应的点击和悬停检查。
- **界面主题：**“底图”里新增“跟随系统 / 浅色 / 深色”，选择记在本地（桌面版记在 `settings.json`）。“跟随系统”时页面不加干预，网页版交给浏览器或 Artifact 页面，桌面版跟随 macOS；选浅色或深色时设置页面根元素的 `data-theme`。桌面版同时设置 Electron 的 `nativeTheme`，所以窗口底色、红绿灯按钮和系统对话框也一起切换。地图颜色按设定不变。
- **沉浸标题栏：**macOS 桌面版用 `titleBarStyle: 'hiddenInset'` 隐藏系统标题栏，红绿灯按钮放在页面顶部一条 40 像素高的条里。这条可以拖动窗口，中间显示文件名和未保存的 ●；页面内容整体下移 52 像素。代价是系统标题栏上那个可拖动的文件图标没有了。`test/desktop.mjs` 新增了顶部条和主题切换的检查。
- **标志：**按 kaankiziltug/logo-design-skill（MIT 许可）的流程，从三个概念里选了 A“涂一格”，做成全套，说明见 `design/logo/GUIDE.md`。8 个图形标志在技能自带的 `svg_audit.py` 里都是 100 分。页面标题前的标志用小尺寸版的画法，线条跟随文字色、涂色跟随主色，所以会随主题切换。
- **应用图标：**最初按 macOS 的圆角网格画了一个自带圆角和阴影的 `.icns`，但在 macOS 27.2 上，系统把它缩小后放进了一个灰色底板。改成铺满 1024 方形画布的图以后，系统会自己裁圆角、加阴影，看起来和原生图标一样。这个结果是用 NSWorkspace 让系统渲染图标、再看截图确认的。开发模式下运行 `npm run desktop` 时，程序坞也显示这个图标。

**第 12 版：阵营、国旗、中英文（2026-11-06）。**

- **阵营数据**在 `src/blocs.js`，成员用地图单位的三位代码写，按本图的边界计。截至 2026 年 11 月并经过检索核实的状态：东帝汶 2025 年 10 月加入东盟；亚美尼亚 2024 年 2 月起冻结集安组织成员资格，没有正式退出；据多方报道阿联酋 2026 年 5 月退出欧佩克（欧佩克官网一度仍列 12 个成员）；美洲国家组织里尼加拉瓜 2023 年退出、委内瑞拉 2019 年退出（有争议）、古巴资格已恢复但不参加；不结盟运动 120 个成员按维基百科整理，没有逐一核对官方名单。冻结和不参加的成员照常画出，在成员列表里变淡并标注；已退出的不画，只列名。
- **华约**按“当年的地域”：苏联取 15 个继承国，捷克斯洛伐克取捷克和斯洛伐克，东德取德国东部 7 个一级行政区（沿上一版对齐过的分界线，含东柏林和诺伊豪斯），阿尔巴尼亚记为 1968 年退出。**欧盟**不含格陵兰。这两种“国家只有一部分算”的情况，在三种绘制里都把相关行政区从国家的斜纹里挖掉、再按它们自己的阵营单独画：WebGL 用模板缓冲，Canvas 和 SVG 用奇偶填充，所以不会盖住单独涂过色的区县。
- **一键涂色**把成员加进当前颜色（华约连同东德各州）；格陵兰没法单独设成未涂色，所以给欧盟一键涂色时它会跟着丹麦变色，提示里会说明，图层本身仍不含格陵兰。
- **国旗**来自 flag-icons（MIT，4:3），`scripts/flags.mjs` 按 Natural Earth 的两位代码给 242 个地图单位配旗，合成一个 1.6 MB 的文件，1:10m 轮廓加载完后才加载。泽凯利亚和阿克罗蒂里用英国国旗；西撒哈拉和比尔泰维勒不显示国旗；已并入其他单位的地区没有单独的旗。页面说明里加了国旗来源。
- **中英文**：界面文字在 `src/i18n.js`；国家名和一级行政区名用 Natural Earth 的中英文名，二级行政区只有原文名。语言选择记在本地，桌面版记在 `settings.json`，主进程据此重建菜单、改窗口标题和对话框。搜索框换成了自己的建议列表（可以用方向键和回车），中英文名和三位代码都能搜。
- **验证**：`test/webgl.mjs` 新增 `blocs` 批次（莱比锡是北约加华约、汉诺威只有北约、华沙两者、莫斯科只有华约、格陵兰只有北约、日德兰欧盟加北约、奥斯陆只有北约、维也纳只有欧盟，都按 WebGL 画面的像素颜色判断；悬停读数、两种一键涂色、不结盟运动 120 面国旗、搜索列表）和 `i18n` 批次（英文界面、英文平面图标注、英文导出、切回中文）。`compare` 批次新增一个开着三个阵营的视图，WebGL 和 Canvas 的差异像素 0.05%。`test/desktop.mjs` 确认了英文菜单和标题。其余各批和原有测试都重跑通过。

**Windows 版（2026-11-06）。** `npm run dist:win` 在 Mac 上用 electron-builder 交叉打包 Windows x64 版，不需要 Wine，输出 NSIS 安装程序（可选安装位置，按用户安装）和免安装的 zip。Windows 图标 `design/logo/kit/icon/AppIcon.ico` 从 macOS 图标的 1024 图生成：留 4.7% 边距、裁成圆角方形，包含 16 到 256 七个尺寸。菜单栏里的应用菜单（`appMenu`）只在 macOS 上加，Windows 的菜单从“文件”开始；沉浸标题栏本来就只在 macOS 上启用，Windows 用系统标题栏。package.json 补了作者和版权，exe 的公司名不再是 Electron 默认的 GitHub, Inc.。在 Mac 上检查过：exe 是 x86-64 的 PE 程序，图标和版本信息都写进去了，`resources/data` 的 415 个数据文件齐全；还没有在 Windows 真机上运行过。

**第 15 版：侧栏布局和自动保存（2026-11-08）。**

- **布局：**页面高度固定为一屏（`100dvh`），`html` 和 `body` 不滚动，只有两个侧栏的内容列各自滚动。工具（阵营、图层、界面、导出和配置）在左侧栏，颜色（画笔、当前颜色、地图底色）在右侧栏，原来地图下方的画笔条、读数行和边界说明都去掉了：画笔改成右侧栏里一行一个，悬停读数和帧率浮在地图左下角，加载提示和操作消息浮在地图顶部，消息 5 秒后淡出（文字仍留在 `#msg` 里）。窗口窄于 900 像素时，侧栏浮在地图上，一次只展开一侧，启动时都是收起的。
- **收起和折叠：**侧栏宽度用 `@property` 注册的 `--lw`、`--rw` 做过渡，收起后是 56 像素的窄栏，内容列保持原宽度滑出窗口边缘，不会挤压变形；快捷键 `[`、`]`。每张卡片的标题是折叠按钮，用 `grid-template-rows: 0fr / 1fr` 做展开动画，收起时内容设为 `inert`。卡片的标题栏和工具按钮由脚本统一包上去，HTML 里只写卡片内容。页面打开时先不加过渡，等布局就位后才开启，以免一打开就看到侧栏收起的动画。
- **编辑显示内容：**点侧栏顶部的铅笔进入编辑模式，每张卡片出现上移、下移、换边和隐藏按钮，标了 `data-item` 的行（各个阵营、图层开关、主题、帧率、导出按钮、配置 JSON、国家和行政区输入框、海洋和背景颜色）右边出现眼睛按钮。隐藏的内容在编辑时半透明显示，退出编辑后不再显示。布局（两侧开合、卡片顺序、折叠和隐藏）作为偏好存成 `layout`，网页版在 localStorage，桌面版在 `settings.json`，不写进配色配置。
- **桌面版自动保存：**主进程收到页面的修改后 300 毫秒内写盘：打开的是项目文件就直接写回这个文件，未命名项目写到设置文件夹里的 `untitled.json`。关闭窗口和退出前会把还没写的修改立刻写完，不再弹出“要保存吗”。启动时依次尝试：命令行或 Finder 传来的文件、上次打开的项目（`settings.lastProject`）、`untitled.json`。只有未命名项目会显示 ●；新建或打开别的项目会替换未命名项目，这时才会询问是否另存为文件。打开旧项目时页面里会迁移旧代码，但文件本身要等第一次修改才会被改写。
- **验证：**新增 `test/layout.mjs`（无头 Chrome）：四种窗口尺寸下页面都不滚动、地图占满剩余高度；左右分工正确、旧说明已删除；收起左栏后地图变宽 244 像素且画布跟着变；快捷键收起右栏；卡片折叠后高度为 0 且 `inert`；编辑模式下隐藏阵营、隐藏一行、上移和换边，退出后生效，刷新并切到英文后仍保留；恢复默认；窄窗口下两侧浮在地图上且一次只开一侧。`test/desktop.mjs` 改为在同一个设置目录上启动三次：第一次确认修改和撤销都直接写回项目文件、新建后未命名项目写进 `untitled.json`、标题带 ●、全程没有弹出询问、布局写进设置；第二次不带文件启动，恢复未命名项目和收起的侧栏，打开项目文件前询问一次，之后 `untitled.json` 被删除；第三次自动打开上次的项目文件。`test/webgl.mjs` 的六批（spots、compare、features、fallback、blocs、i18n）全部重跑通过，i18n 批里原来检查边界说明的那一项改为检查侧栏和卡片标题。README 的五张截图按新布局重新生成。
